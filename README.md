# U15静岡プロコンサーバー
Combine Google Blockly and Procon Game Server.

U15静岡プロコンサーバーは U-16プログラミングコンテスト静岡大会 での使用を想定したサーバです。

ビジュアルプログラミングの一つである[blockly](https://github.com/google/blockly)を用いて、
プログラミング初学者が気軽にプログラミングコンテストに参加できる環境づくりを目指しています。
ゲーム仕様は[AsahikawaProcon-Server](https://github.com/hal1437/AsahikawaProcon-Server)を参考に、
ブラウザ上でゲームの実行が可能です。

## 派生元

本リポジトリは以下の系譜のフォークです。

U15長野プロコンサーバー
→ [U15一関プロコンサーバー](https://github.com/U15-Ichinoseki/blockly-chaser-ichinoseki) (v4.5.0)
→ 本リポジトリ（静岡大会仕様）

参加者が練習に使用する [chaser.u15-ichinoseki.org](https://chaser.u15-ichinoseki.org/) は
一関版 v4.5.0 が稼働しており、本リポジトリはその配信ファイルと同一の内容から分岐しています。
そのため、参加者が練習環境で保存した `.blch` ファイルをそのまま読み込めます。

上流の更新を取り込む場合:

```bash
git fetch upstream
git merge upstream/master
```

## 機能
- プログラミング
	- プログラムの実行・停止
	- ゲーム用ブロックの追加
	- エラー表示
	- プログラムの保存
		- 保存ボタンによる手動保存(JSON圧縮形式 `.blch`)
		- プログラム実行時の自動保存
	- プログラムのロード
		- 開くボタンによる任意プログラムのロード
		- 前回実行したプログラムのロード
	- コードの表示
		- Python
		- JavaScript
	- 上級編
- チュートリアル
	- 操作方法等のチュートリアルページ
- ゲーム
    - ゲームの開始・終了
    - マップ自動生成
    - CPU対戦
    - 他プレイヤー同士のゲーム観戦

## 動作環境
- Windows 11 / macOS 14
- Node.js 18 以上を推奨（開発時の確認は Node.js 25 系）

## セットアップ

```bash
git clone <本リポジトリのURL> blockly-chaser-shizuoka
cd blockly-chaser-shizuoka
npm install
npm start
```

## 動作確認
- サーバー機のブラウザから `http://localhost:3000/`
- 参加者端末からは `http://<サーバー機のIPアドレス>:3000/`

ポートは環境変数 `PORT` で変更できます。

```bash
PORT=8080 npm start
```

## トーナメント表

対戦表を `/tournament` で参加者・観客に見せられます。この画面は認証不要で、
30秒ごとに自動で更新されます。

運営は `/tournament/admin` で操作します(権限は試合動画と同じ `ADMIN_KEY`)。

### 進め方

1. **参加者を登録する** — 名前と所属を入力します。
   並び順はシード順として扱われ、上の選手ほど有利な山に入ります。
   人数が2のべき乗でない場合、上から順に不戦勝が割り当たります。
2. **対戦表を作る** — 「対戦表を作る」を押します。
   **作り直すとそれまでの勝敗はすべて消えます。** 参加者を並べ終えてから押してください。
3. **勝敗を入力する** — 各試合の勝者・スコア・備考・使用マップ・試合動画を記録します。
   勝者は自動で次の回戦へ進みます。

### サーバーが記録した試合結果

このサーバーで行われた試合の結果は自動で記録され、管理画面の下部に並びます。

**対戦表には自動で反映されません。** 取り込む試合を選んで「取り込む」を押してください。
大会中に誤って反映されると取り返しがつかないため、反映は必ず運営の操作を挟みます。

選手名が対戦表と一致しない場合は取り込みません。
ゲーム側の cool / hot と対戦表の cool / hot が逆でも、名前で突き合わせて正しく入れ替えます。

### データの置き場所

| ファイル | 内容 |
|---|---|
| `load_data/tournament/tournament.json` | 対戦表。操作のたびに保存される |
| `load_data/tournament/results.jsonl` | 自動記録された試合結果。追記のみ |

`tournament.json` は一時ファイル経由で置き換えるため、
書き込み中にサーバーが落ちても壊れたファイルは残りません。

## 試合動画

運営が用意した試合動画を、参加者がメニューの「試合動画」から閲覧できます。

### 動画を追加する

`load_data/movie_data/` に動画ファイルを置くだけで一覧に出ます。サーバーの再起動は不要です。

対応形式は `.mp4` / `.webm` / `.m4v` の3種類です。
ブラウザがそのまま再生できる形式に限っているため、`.mov` や `.avi` は一覧に出ません。
変換するには次のようにします。

```bash
ffmpeg -i 元の動画.mov -c:v libx264 -pix_fmt yuv420p -movflags +faststart 決勝戦.mp4
```

`-movflags +faststart` を付けると、ダウンロードが終わる前に再生を始められます。

### タイトルや説明をつける

`load_data/movie_data/movies.json` に書きます。

```json
{
  "movies": [
    {
      "id": "final-2026",
      "file": "決勝戦.mp4",
      "title": "2026年 決勝戦",
      "description": "終盤の判断に注目してください。",
      "date": "2026-10-12",
      "order": 1
    }
  ]
}
```

`order` の小さい順に並びます。`movies.json` に書かなかったファイルは、
ファイル名をタイトルとして一覧の末尾に並びます。

`id` は再生ページの URL (`/movies/<id>`) になります。

### 管理画面から操作する

`/movies/admin` で、アップロード・タイトルの編集・非公開の切り替えができます。

誰がこの画面を開けるかは環境変数 `ADMIN_KEY` で決まります。

| `ADMIN_KEY` | 開ける人 |
|---|---|
| 未設定 | サーバー機のブラウザ (localhost) のみ |
| 設定済 | 合言葉を入力した人 |

運営が別の端末から操作したい場合は、合言葉を設定して起動します。

```bash
ADMIN_KEY=好きな合言葉 PORT=3000 npm start
```

これは大会運営上の仕切りであって、強度のある認証ではありません。
会場LAN内での運用を前提としています。

### 動画を非公開にする

管理画面の「動画を非公開にする」を押すと、ファイルが
`load_data/movie_data/_hidden/` へ移動し、一覧から消えます。削除はされません。
戻したいときは、そのファイルを1つ上の階層へ移動してください。

`movies.json` から消すだけではファイルが残っているため、一覧に出続けます。

## 大会運営時の注意

- **会場LAN内で完結させることを推奨します。** インターネットに公開すると、
  合言葉が推測された場合に部外者が試合に乱入できます。
- 対戦状態はすべてサーバープロセスのメモリ上に保持されます。
  サーバーを再起動すると進行中の試合は失われます。
- `node_modules` は同期フォルダ（Google Drive / iCloud 等）に置かないでください。

## テスト

```bash
npm test
```

`node --test` を使っています(追加の依存なし)。
マップ定義の検証、動画とトーナメントの処理、権限、
そして実際に CPU と1試合戦う結合テストまで含みます。

テストファイルは同じ `load_data/` を読み書きするため、直列で実行します。
